# Engineering Rules

Never generate placeholder code.

Never use any.

Always use strict typing.

Prefer Signals.

Prefer standalone components.

No duplicated SCSS.

No duplicated HTML.

No magic strings.

Prefer composition.

Use semantic HTML.

Follow accessibility.

Optimize for Lighthouse.

Optimize for Core Web Vitals.

Optimize for SEO.

Never break existing components.

Always explain architectural decisions before coding.

Implement incrementally.

After every task ask what should be built next.
